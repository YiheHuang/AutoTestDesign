# 被测应用风险分析报告

> Task Management Platform — 任务管理平台

> 以下风险分析由AutoTestDesign自动化测试工具辅助生成

---

## 1. 被测应用概述

### 1.1 应用描述

被测应用是一个基于 Flask + SQLite 的任务管理平台 (Task Management Platform)，提供用户认证、项目管理和任务协作三大核心功能模块。系统采用 RESTful API 架构，通过 Blueprint 实现模块化路由管理。

### 1.2 功能范围

| 模块 | 功能 | API 端点 |
|------|------|---------|
| 用户管理 | 注册、登录、密码重置、登出 | `/api/register`, `/api/login`, `/api/forgot-password`, `/api/reset-password`, `/api/logout` |
| 项目管理 | 创建、查看、编辑、删除项目 | `/api/projects` (GET/POST), `/api/projects/<id>` (GET/PUT/DELETE) |
| 任务管理 | 任务 CRUD、分配、筛选、统计 | `/api/projects/<id>/tasks`, `/api/tasks/<id>`, `/api/users/<name>/tasks` |

### 1.3 技术栈

| 层 | 技术 |
|----|------|
| 后端 | Python 3.11+ / Flask 3.0 |
| 数据 | SQLite |
| 认证 | SHA-256 密码哈希 + Token 密码重置 |
| 架构 | Blueprint 模块化路由 + 工厂模式 |

## 2. 风险识别方法论

### 2.1 方法概述

本报告采用 **FMEA (Failure Mode and Effects Analysis)** 与 **AI 辅助分析** 相结合的混合方法：

1. **功能分解**: 将系统分解为 7 个独立需求条目
2. **AI 评估**: 使用 AutoTestDesign v2.2 工具，由 LLM (GPT-4o via yunwu.ai) 对每项需求评估风险等级、风险因素和测试优先级
3. **人工复审**: 对 AI 评估结果进行合理性校验和补充

### 2.2 风险维度

| 维度 | 评估标准 | 权重 |
|------|---------|------|
| 功能关键性 | 失效后对核心业务流程的影响程度 | 高 |
| 数据敏感性 | 是否涉及密码、个人信息等敏感数据 | 高 |
| 安全影响 | 是否存在认证绕过、权限提升等安全风险 | 高 |
| 业务复杂度 | 逻辑分支、条件组合、状态转换的复杂度 | 中 |
| 用户可见度 | 用户直接交互 vs 后台处理 | 中 |

### 2.3 风险等级定义

| 等级 | 定义 |
|------|------|
| **High** | 涉及核心功能、安全认证、敏感数据(密码/个人信息)、或复杂业务逻辑。失效直接导致系统不可用或安全漏洞。 |
| **Medium** | 一般业务功能，有一定复杂度但非安全关键。失效影响用户体验但不阻塞核心流程。 |
| **Low** | 辅助功能、简单展示逻辑、非关键路径。失效影响较小或有替代方案。 |

## 3. 功能模块风险分析

### 3.1 风险矩阵总览

| 需求ID | 功能模块 | 风险等级 | 测试优先级 | 核心风险因素 |
|--------|---------|---------|-----------|-------------|
| REQ-001 | 用户注册 | **High** | **High** | 密码验证、敏感数据、安全关键 |
| REQ-002 | 用户登录 | **High** | **High** | 密码验证、锁定逻辑、认证安全 |
| REQ-003 | 密码重置 | **High** | **High** | 密码重置、Token 验证、敏感数据 |
| REQ-004 | 项目管理 | **Medium** | **Medium** | 级联删除、数据完整性 |
| REQ-005 | 任务管理 | **Low** | **Low** | CRUD 操作、筛选逻辑 |
| REQ-006 | 任务分配 | **Medium** | **Medium** | 用户验证、业务流程关联 |
| REQ-007 | 任务统计 | **Low** | **Low** | 数据展示、非核心功能 |

### 3.2 详细分析

#### REQ-001: 用户注册 (High Risk / High Priority)

**风险因素**:
- 5 个输入字段，每个字段有独立的验证规则
- 涉及密码复杂度验证（至少 3/4 种字符类型）
- 用户名和邮箱的唯一性检查（与数据库交互）
- 年龄范围验证（数值边界条件）

**潜在失效模式**:
- 密码复杂度验证绕过，允许弱密码注册
- 唯一性检查失效，产生重复用户名或邮箱
- 年龄边界值处理错误（17/18/120/121）

**建议测试策略**:
- 等价类划分: 每个字段 2+ 有效类 + 3+ 无效类
- 边界值分析: age (17,18,19,119,120,121), username (2,3,4,19,20,21)
- 判定表: 唯一性 + 密码复杂度 + 格式验证的组合规则

---

#### REQ-002: 用户登录 (High Risk / High Priority)

**风险因素**:
- 密码验证与数据库交互
- 5 次失败锁定 30 分钟的复杂状态转换
- 锁定期间的时间计算精度
- 状态转换: 未登录 → 登录中 → 已登录/已锁定 → 自动解锁

**潜在失效模式**:
- 锁定计数器未重置导致永久锁定
- 30 分钟时间窗口计算错误（时区/精度问题）
- 凭据验证绕过或密码比较漏洞

**建议测试策略**:
- 判定表: 密码正确/错误 × 锁定/未锁定 条件组合
- 状态转换: All-States 覆盖 5 个状态
- 边界值: 4 次失败(未锁) vs 5 次失败(锁定)

---

#### REQ-003: 密码重置 (High Risk / High Priority)

**风险因素**:
- Token 生成与验证的安全机制
- 1 小时过期时间的时间验证
- 安全提示的统一性（不暴露邮箱是否注册）
- 新旧密码的隔离

**潜在失效模式**:
- Token 过期判断错误（时间比较逻辑缺陷）
- Token 未标记为已使用（可重复使用重置）
- 新密码复杂度验证绕过

**建议测试策略**:
- 边界值: 新密码长度 (7,8,9,31,32,33)
- Token 验证: 有效/无效/过期/已使用 四种状态
- 安全测试: 未注册邮箱不暴露信息

---

#### REQ-004: 项目管理 (Medium Risk / Medium Priority)

**风险因素**:
- 级联删除逻辑（删除项目时需同时删除任务）
- 数据完整性（孤儿任务问题）
- 项目名称长度验证

**潜在失效模式**:
- 删除项目时未级联删除任务，产生孤儿数据
- 项目名称长度验证缺失或绕过

**建议测试策略**:
- 集成测试: 删除项目后验证任务状态
- 边界值: 项目名称长度 (1, 100, 101 字符)

---

#### REQ-005: 任务管理 (Low Risk / Low Priority)

**风险因素**:
- 枚举值的严格校验（优先级 Low/Medium/High）
- 状态值校验（todo/in_progress/done）
- 筛选功能的正确性

**潜在失效模式**:
- 非法优先级值被静默接受为默认值
- 状态筛选使用模糊匹配导致结果不精确
- 项目不存在时未正确拒绝创建

**建议测试策略**:
- 等价类划分: 每个枚举字段的有效/无效值
- 集成测试: 筛选组合的正确性

---

#### REQ-006: 任务分配 (Medium Risk / Medium Priority)

**风险因素**:
- 负责人存在性验证
- 任务与用户的关联关系

**潜在失效模式**:
- 任务分配给不存在的用户
- 用户任务列表查询遗漏已分配任务

**建议测试策略**:
- 等价类划分: 有效用户名 vs 不存在用户名
- 集成测试: 分配后验证用户任务列表

---

#### REQ-007: 任务统计 (Low Risk / Low Priority)

**风险因素**:
- 统计数字的准确性
- 分组计数的完整性

**潜在失效模式**:
- 统计计数与实际数量不符
- 分组维度缺失（如某些优先级任务未被统计）

**建议测试策略**:
- 数据驱动测试: 准备已知数量的任务，验证统计结果

## 4. 技术风险分析

### 4.1 安全风险

| 风险项 | 等级 | 影响 | 缓解措施 |
|--------|------|------|---------|
| 密码哈希强度 | High | SHA-256 无盐值，彩虹表攻击 | 升级为 bcrypt/scrypt |
| Token 可预测性 | Low | 使用 `secrets.token_urlsafe` 已足够 | 确保密钥不泄露 |
| SQL 注入 | Low | 使用参数化查询 (`?` 占位符) | 代码审查确认 |


### 4.2 数据完整性风险

| 风险项 | 等级 | 影响 | 缓解措施 |
|--------|------|------|---------|
| 孤儿任务 | Medium | 删除项目后任务残留 | 实现级联删除 |
| 外键约束缺失 | Medium | 数据引用完整性问题 | 添加 FOREIGN KEY 约束 |
| 并发写入 | Low | 单用户场景影响小 | 如扩展需加写锁 |

### 4.3 性能风险

| 风险项 | 等级 | 影响 | 缓解措施 |
|--------|------|------|---------|
| LIKE 模糊查询 | Low | 状态筛选使用 `LIKE` 而非精确匹配 | 改为 `=` 精确匹配 |
| 全表扫描 | Low | 当前数据量小，无显著影响 | 如扩展需加索引 |
| SQLite 并发限制 | Low | 单进程写入锁 | 如扩展到多用户，迁移到 PostgreSQL |
